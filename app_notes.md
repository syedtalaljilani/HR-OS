# HR OS — Working Memory (auto-maintained)

## Objective
- Candidate email Chat: replies must appear in the chat, be answered **once** per message, and actually answer the candidate's query; interview invitation email goes out **once** per real status transition; one interview reminder/follow-up sent **~1 day before** the interview (once); Chat application link must work; Chat page responsive; chat tab removed from candidate view.
- Candidate **reschedule + remote-interview** flow: "not available" → interview email includes a public reschedule link; candidate picks from available slots → previous interview auto-cancelled, new one scheduled + invited; candidate can also request a **remote interview** (with reason); HR accepts (sets meeting link + emails confirmation, interview becomes remote) or declines (emails update). Chat page auto-checks inbox (60s polling) so candidate replies appear live.
- Candidate **new-slot human-in-the-loop** flow (NEW): when a candidate emails a request to move the interview, the AI reply agent parses the message — if a date (but no time) is given, the agent replies asking for the time (records only an `awaiting_time` request, nothing for HR yet); once the time arrives the request is completed and appears PENDING on the HR dashboard with the proposed date+time; HR **accepts** (interview rescheduled to the proposed time, old one cancelled, new invite emailed) or **declines** (stays scheduled, candidate emailed).
- **CV OCR fallback (scanned/image PDFs)**: fast path = pypdf/docx native text (no OCR); if a PDF yields <60 chars → PyMuPDF renders first `OCR_MAX_PAGES` (5) pages at `OCR_DPI` (150) as base64 PNGs → **one batched** `/api/chat` vision call to `OLLAMA_OCR_MODEL` (`deepseek-ocr`, already pulled in Ollama) → parse as usual. Startup background `warm_ocr_model()` thread avoids the multi-GB cold load on the first scanned CV. Settings: `OLLAMA_OCR_MODEL/OCR_MAX_PAGES/OCR_DPI/OCR_WARMUP_ON_STARTUP`; de-OCR strips `###`/`<|end|>` branch markers. `extract_profile_from_cv` returns an extra `ocr` flag. Verified: image-only PDF OCR+parse ≈ 9–18s (warm) with clean name/email/phone/skills; normal PDF fast path ≈ 4s; same-file cache ≈ 1ms; live health 200.
- Make candidate **apply submission** fail-proof: three root causes fixed (TALENT_POOL enum, salary `Decimal` parse crash, soft-deleted-candidate unique-violation 500). "Remote" interview emails must NOT contain the auto Google Maps pin (meeting-link locations get a plain `How to join`).
